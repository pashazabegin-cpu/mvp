# MVP — первый экран (hero)

Прелоадер (Lottie) → интро → 5 слайдов по 7 секунд с прогрессом в навигации → переход наклонными полосами (16.76°).
Один модуль на чистом TypeScript + GSAP, без фреймворков. Работает поверх серверной разметки.

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # проверка типов + сборка в dist/
```

Демо-сборка для показа: `npm run build` → папка `dist/`. Открывается двойным кликом по `index.html`, без сервера — JS, CSS, шрифты и прелоадер встроены в страницу (сжаты, читать их не нужно), видео и картинки лежат рядом в `hero/`.

Демо-параметры: `?slide=3` — сразу на слайд, `?pause` — без автопрокрутки, `?nopreload` — без прелоадера, `?static` — мгновенно доигрывать анимации (для скриншотов).

## Для разработчика: с чего начать

- **Состояние:** экран готов и согласован с дизайнером (десктоп 1440×900 и мобильный 320×700). Переписывать не нужно — нужно перенести в шаблон сайта и подставить контент.
- **Стек:** TypeScript + Vite, анимации — GSAP 3 (вместе с плагином SplitText), прелоадер — lottie-web. Без фреймворков и без jQuery. На сайте, судя по его сборке, тоже Vite + TypeScript (`app.ts`), поэтому модуль подключается одним импортом (см. «Как подключить» ниже).
- **Исходники** — `index.html` (разметка), `src/hero/` (скрипты и стили), `public/hero/` (видео и картинки). Всё остальное — обвязка для демо-страницы: `src/main.ts` и `src/demo.css`, плагин в `vite.config.ts` (встраивает всё в один html), `scripts/make-artifact.mjs` (готовит демо для ссылки). На сайт их переносить не нужно.
- **Макеты:** Figma, файл `qr4DIyEm4sBXAFn5MM1ycW`, страница «web 2.0»: на каждый слайд по кадру 1440×900 (десктоп) и 320×700 (мобильный).

### Контент — то, что выносится в поля CMS

Вся смена контента — только в разметке, JS и CSS трогать не нужно:

| Где | Что менять |
|---|---|
| `<article class="hero-slide">` | `data-accent` — цвет полосы прогресса в навигации; `data-focus` — какую точку фона держать в кадре на узких экранах (x в px холста 1600) |
| `<video data-hero-video>` | `src` и `poster` (1080p H.264 без звука, постер — первый кадр). Атрибут `data-deferred` у 2-го и 3-го видео не убирать |
| `.hero-tag` | две строки плашки (город, дата) и её цвет `style="--tag:…"` |
| `.award-logo`, `.forum-logo`, `.kviz-logo`, `.rating-logo`, `.duo-title` | картинка логотипа и её `alt`; размеры (`width`/`height`) — по макету |
| `[data-anim="lines"]` | текст описания. Можно `<br>` и `<span class="nobr">` (неразрывный кусок); на строки текст режется автоматически |
| `.hero-btn` | подпись и ссылка `href` |
| `.hero-chrome` | ссылка и логотип партнёра, «Связаться с нами», Telegram, ВКонтакте |
| `.hero-nav__item` | подписи: текст и `data-text` должны совпадать (копия текста нужна для анимации при наведении) |

Слайды и пункты навигации идут в одном порядке, `data-goto` — 0, 1, 2… Пять текущих слайдов — пять разных раскладок по макету (позиции заданы в `hero.css` по классам). Новый слайд по образцу существующего — копия `<article>` с другим контентом плюс пункт навигации; слайд с новой раскладкой — плюс стили позиций в `hero.css`.

### Что не трогать

- Числа из Figma: `style` у `.stripe`, значения `data-glow`, `--x`/`--y`/`--mx`/`--my` в `hero.css`, массивы в `rating.ts`. Это раскладка 1:1 с макетом.
- HTML-слои под `<canvas data-gl>` в «Рейтинге» и «Премии и форуме». Это запасной вариант без WebGL, а `.duo-logo` ещё и «ручки», за которыми шейдер следит при анимации, — удалять нельзя.
- Не вешать CSS `transition` на свойства, которые анимирует GSAP, — анимации начнут конфликтовать. Для ховера анимируется внутренний элемент, GSAP — внешний (как в `.hc-mark`).

### Что ещё нужно уточнить по контенту

- Ссылки — заглушки: кнопки (`#apply`, `#forum`, `#kvizmass`, `#rating`, `#duo`), «Связаться с нами» (`#contacts`), соцсети (`https://t.me/`, `https://vk.com/`).
- Даты взяты из макета: «24 / 30 мая 2025» на «Премии», «Форуме» и «Премии и форуме»; «13 декабря 2026» на «Квизмасе» (в десктопном макете — 2027).
- Описание «Премии и форума» повторяет текст «Квизмаса» — как в макете, нужен свой текст.
- Подпись первой кнопки — «Подать заяву», как в макете.
- Логотип «КВИЗМАС» — PNG (шрифт Object Sans); лучше заменить на SVG.
- Кнопка «Меню» на мобильном — только разметка, само меню открывает сайт.

## Как подключить в существующий сайт (Vite + `app.ts`)

1. `npm i gsap lottie-web`
2. Скопировать `src/hero/` в проект, ассеты `public/hero/` — в папку статики (например `/assets/2026/hero/`) и поправить пути в разметке и в `@font-face` в `hero.css`. Шрифты Space Grotesk уже лежат на сайте в `/assets/2026/fonts/` — можно сослаться на них.
3. В `app.ts`:
   ```ts
   import './hero/hero.css';
   import { initHero } from './hero';

   const el = document.querySelector<HTMLElement>('[data-hero]');
   if (el) initHero(el, { onReady() { /* прелоадер ушёл — можно запускать остальную анимацию страницы */ } });
   ```
4. Разметку `<section class="hero" data-hero>…</section>` из `index.html` перенести в шаблон главной.

API: `initHero(el, options)` возвращает `{ next, prev, goTo(i), pause, play, destroy }`.
Опции: `autoplay` (мс, по умолчанию 7000; в разметке — `data-autoplay`), `angle` (16.76), `stripCount` (10), `revealDuration` (0.5), `stripStagger` (0.04), `zoomFrom` (1.2), `zoomDuration` (0.9), `onReady`, `onChange(i)`.

## Раскладка

- **Десктоп — макет 1440×900.** Интерфейс (`.hero-ui`) масштабируется так, чтобы кадр 1440×900 целиком влез в экран, а по ширине тянется сетка макета: 14 колонок, поля 60, межколонник 10 (`--col` — шаг колонки, 95 при 1440). Контент начинается со 2-й колонки, описание «Рейтинга» — с 9-й, «Связаться с нами» — с 12-й, соцсети прижаты к правому полю, знак по центру, навигация — со 2-й по 13-ю колонку. Шапка привязана к верху, навигация к низу, контент — к центру по высоте.
- Фон (`.hero-canvas`) — холст 1600×900 по «cover»: это кадр 1440 из Figma плюс по 80 px запаса слева и справа, чтобы на 16:9 и шире не было пустых краёв. Координаты фона в разметке и шейдерах — в пикселях этого холста (x из Figma + 80).
- **Мобильный — макет 320×700 + блок партнёра (кадр до 863)**, включается на вертикальных экранах (`max-aspect-ratio: 4/5`, тот же запрос — `MOBILE_QUERY` в `index.ts`). Всё масштабируется по ширине экрана (ширина / 320), поэтому логотипы встают по сетке на всю ширину с полями 20. Первый экран — высота экрана: шапка «Меню» и KV сверху, тег, логотип, описание, кнопка и полосы — от низа первого экрана, под ним блок партнёра BetBoom. Реальные телефоны ниже макета (700 px макета на первый экран; у iPhone 13 mini в браузере около 530), поэтому нехватка высоты сначала забирается из пустых зазоров — кнопка→полосы до 48 и под полосами до 16, — а остаток из зоны KV: фон слайда уменьшается (0.6…1, считается в `fit()` для каждого слайда), чтобы главный объект оставался над текстом. Градиент поверх KV — обычное наложение (без multiply), едет вместе с контентом. WebGL на мобильном не создаётся: «Рейтинг» и «Премия и форум» — готовые рендеры мобильных кадров (`hero/rating/bg-mob.jpg`, `hero/duo/bg-mob.jpg`), десктопные слои и текстуры там не грузятся (`loading="lazy"` на скрытых картинках). При повороте планшета в горизонталь шейдеры создаются на лету.
- Кнопка «Меню» (`[data-hero-menu]`) только разметка — меню открывает сайт.

## Заметки

- **Почему «Рейтинг» и «Премия и форум» на WebGL.** Их фон собран из режимов наложения (overlay, hard-light, color-dodge, plus-lighter, Linear burn). CSS `mix-blend-mode` внутри анимированной маски перехода Chrome рисует с артефактами (белые и пустые прямоугольники) и тормозит при первом показе. Шейдер считает те же формулы сам, для браузера это обычная картинка, как видео. Шейдеры компилируются и рисуют первый кадр ещё под прелоадером.
- Фон «Премии и форума» — рендер из Figma 2x, 1600×900 с запасом по бокам (`bg-base.jpg` без луча, `bg-ray.jpg` с лучом). Луч раскрывается кругом из точки внизу, в конце картинка 1:1 с макетом. Синий логотип — честный Linear burn, розовый — Screen; оба двигаются за курсором (GSAP анимирует невидимые `.duo-logo`, шейдер читает их положение).
- Без WebGL остаётся HTML-версия этих слайдов (слои в разметке под `<canvas data-gl>`).
- Текстуры WebGL задаются в `data-tex-*` у canvas. В демо-сборке они встраиваются в страницу (с file:// браузер не даёт грузить картинки в WebGL), на сайте — обычные ссылки.
- Видео перекодированы в 1080p H.264 без звука, с индексом в начале файла (играют до полной загрузки): «Премия» 7.4 МБ → 0.77 МБ, «Форум» 14 МБ → 2.6 МБ (2 Мбит/с), «Квизмас» 0.9 МБ → 0.6 МБ. У каждого есть постер — первый кадр.
- Видео первого слайда грузится сразу (его ждёт прелоадер), видео «Форума» и «Квизмаса» — после прелоадера (`data-deferred`), чтобы не отнимать канал у первого экрана.
- `prefers-reduced-motion`: переход становится простым растворением, магнит и параллакс отключаются.
- На тач-устройствах — свайп; магнит к курсору не включается.
- Рендеры фонов из Figma (2x для десктопа, 3x для мобильного) делаются так: копия кадра без интерфейса, расширенная на запас по бокам, `rescale`, скриншот, копия удаляется.
